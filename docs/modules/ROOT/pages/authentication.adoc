= Dual-Mode Authentication (`SELF_MANAGEMENT` | `KEYCLOAK`)
:toc:

The OCSP Responder and Admin Console (`http://localhost:3002`) support two mutually exclusive authentication modes configured via `app.auth.mode`:

[source,yaml]
----
app:
  auth:
    mode: ${APP_AUTH_MODE:${AUTH_MODE:KEYCLOAK}} # SELF_MANAGEMENT or KEYCLOAK
----

== Core Ownership Rule: One Writer Per Data Domain

Exactly one system owns identity per deployment. Two writers are never allowed for the same data:

[cols="2,2,2", options="header"]
|===
| Data Domain | `SELF_MANAGEMENT` | `KEYCLOAK`

| *Credentials, MFA, Sessions*
| App DB (`ocsp.users.password_hash`)
| Keycloak IAM (`ocsp-keycloak`)

| *Identity* (`username`, `email`, `full_name`, `enabled`)
| App DB (`ocsp.users`, `auth_source = LOCAL`)
| Keycloak (App DB holds a read-only replica keyed by `external_id`, `auth_source = KEYCLOAK`)

| *App Profile* (`roles`, `tenant_id`, `preferences_json`, `audit`)
| App DB (`ocsp.users`, `ocsp.user_roles`)
| App DB (`ocsp.users`, `ocsp.user_roles`)
|===

== UUID Data Model (`V9__dual_mode_identity.sql`)

* **`users.id` (`CHAR(36)` UUID PK)**: Internal immutable primary key used by all foreign keys (`user_roles.user_id`).
* **`users.external_id` (`VARCHAR(255)` UNIQUE)**: Keycloak `sub` claim in `KEYCLOAK` mode (`NULL` for pure `LOCAL` users).
* **`users.auth_source`**: `LOCAL` or `KEYCLOAK`.
* **`users.password_hash`**: BCrypt hash for `LOCAL` users only; **always `NULL` for `KEYCLOAK` users**.
* **`users.tenant_id` & `users.preferences_json`**: Application-owned profile columns.
* **`users.deleted_at`**: Soft-delete timestamp (supports GDPR anonymization).
* **`identity_outbox`**: Outbox/retry queue for non-transactional Keycloak Admin API operations.

== Strategy Interface (`IdentityService`) & Uniform `InternalPrincipal`

* **`IdentityService`** (`createUser`, `updateUser`, `setEnabled`, `resetPassword`, `deleteUser`) has two implementations selected by `@Conditional`:
  - `LocalIdentityService` (`app.auth.mode=SELF_MANAGEMENT`): Writes directly to MariaDB and hashes passwords with BCrypt.
  - `KeycloakIdentityService` (`app.auth.mode=KEYCLOAK`): Calls `KeycloakAdminClient` first using the least-privilege `ocsp-user-sync` service account (`view-users`, `manage-users`), then upserts the DB replica by `external_id` (with `password_hash = null`).
* **One `InternalPrincipal`**: Both `DatabaseUserDetailsService` (`SELF_MANAGEMENT`) and `KeycloakJwtAuthenticationConverter` (`KEYCLOAK`) produce the exact same `InternalPrincipal` (`userId`, `username`, `email`, `fullName`, `tenantId`, `authSource`, `roles`). Business code never checks `app.auth.mode`.
* **UI Enforcement**: In `KEYCLOAK` mode, `UserManagementPage.js` hides password fields so operators never submit credentials to the app.

== Keycloak OIDC Configuration (`keycloak/realm-export.json`)

* **Realm**: `incert`
* **Console Client**: `ocsp-console` (Public client, redirect URIs `http://localhost:3002/*`, `http://localhost:3000/*`)
* **Service Account Client**: `ocsp-user-sync` (Confidential client, `serviceAccountsEnabled: true`, least-privilege `realm-management` roles: `view-users`, `manage-users`)
* **Default Users**: `admin` / `changeme`, `operator` / `changeme`, `auditor` / `changeme`.

= RabbitMQ Strict mTLS & Zero-REST Reconciliation
:toc:

All communication between `kms-simulator` and `ocsp-responder` takes place asynchronously over **RabbitMQ AMQPS (port `5671`)** with strict mutual TLS (`verify_peer`, `fail_if_no_peer_cert = true`). There is **zero HTTP/REST coupling** between the two systems.

== 4-Queue RabbitMQ Topology

All queues bind to the durable direct exchange `incert.certificate.status` (configured via `OcspRabbitMqProperties` / `ocsp.rabbitmq.*` in `application.yml` and `application-dev.yml`):

[cols="2,2,2,3", options="header"]
|===
| Queue Name | Routing Key | Producer -> Consumer | Purpose

| `ocsp.certificate.status`
| `incert.certificate.status.v1`
| KMS `OutboxRelayJob` -> OCSP `CertificateStatusListener`
| Delivers `CertificateStatusEvent` messages (`GOOD`, `REVOKED`) with `message_id = outbox.event_id`.

| `ocsp.certificate.status.dlq`
| `ocsp.certificate.status.dlq` (on DLX `incert.certificate.status.dlx`)
| RabbitMQ Broker -> DLQ
| Captures rejected poison messages (`default-requeue-rejected: false`) after retry exhaustion.

| `ocsp.reconciliation.manifest`
| `incert.reconciliation.manifest.v1`
| KMS `KmsReconciliationService` -> OCSP `OutboxReconciliationService`
| Broadcasts `OutboxManifestEvent` every 3 seconds (and on demand) containing outbox counts, event IDs, and certificate digests.

| `kms.reconciliation.request`
| `incert.reconciliation.request.v1`
| OCSP `OutboxReconciliationService` -> KMS `KmsReconciliationService`
| Sends `ReconciliationCommandMessage` (`REQUEST_MANIFEST` or `REPLAY_EVENTS` with missing/failed event IDs and serials).
|===

== Failure Tracking with `AmqpHeaders.MESSAGE_ID` & `DELIVERY_TAG`

When `CertificateStatusListener` receives a message on `ocsp.certificate.status`:

1. It extracts `@Header(AmqpHeaders.MESSAGE_ID) String messageId` (which KMS sets to the `outbox_event.event_id` UUID) and `@Header(AmqpHeaders.DELIVERY_TAG) Long deliveryTag`.
2. If JSON parsing or processing fails, `InboxFailureRecorder.recordFailure(...)` runs in an independent transaction (`@Transactional(propagation = Propagation.REQUIRES_NEW)`) so the `FAILED` record in `ocsp.inbox_event` (storing `event_id`, `delivery_tag`, and `error_message`) commits even when the listener throws `AmqpRejectAndDontRequeueException`.
3. Because `event_id` matches the KMS Outbox UUID, the Inbox Audit page (`http://localhost:3002/inbox`) and `OutboxReconciliationService` can request an exact replay of that failed event over RabbitMQ.

== Configurable RabbitMQ TLS (`RabbitMqTlsProperties`)

Configured under `rabbitmq.tls.*` in `application.yml` and `application-dev.yml`:

[source,yaml]
----
rabbitmq:
  tls:
    enabled: ${RABBITMQ_TLS_ENABLED:${security.tls.enabled:true}}
    tls-port: ${RABBITMQ_TLS_PORT:5671}
    plaintext-port: ${RABBITMQ_PLAINTEXT_PORT:5672}
----

When `rabbitmq.tls.enabled` is `false`, `RabbitMqConfig.rabbitMqTlsPortCustomizer()` switches the connection port from `tls-port` (`5671`) to `plaintext-port` (`5672`).

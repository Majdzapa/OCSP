= Keycloak Sync, Outbox Retry & Mode Migration
:toc:

In `app.auth.mode=KEYCLOAK`, Keycloak is the authoritative owner of user identity and credentials, while `ocsp.users` maintains a read-only identity replica keyed by `external_id` (`sub`).

== 1. Three-Layer Keycloak Synchronization (`KeycloakSyncService`)

All synchronization handlers are **idempotent upserts keyed by `external_id`** (never joined on mutable `username` or unverified `email`):

1. **JIT Provisioning on Login (`KeycloakJwtAuthenticationConverter`)**:
   * On every authenticated JWT request, `KeycloakSyncService.upsertFromTokenClaims(...)` creates the local replica if missing or refreshes `username`, `email`, `email_verified`, and `full_name` from token claims.
   * Links an existing `LOCAL` account **only** when `email_verified == true` and the verified email matches.
   * Never stores passwords or raw tokens (`password_hash = null`).
2. **Webhook Event Listener (`POST /api/v1/internal/keycloak/events`)**:
   * Secured via `X-Webhook-Secret` (`keycloak.webhook-secret`).
   * Handles `CREATE`, `UPDATE`, `DISABLE`, and `DELETE` events idempotently by `external_id`.
3. **Nightly Reconciliation Job (`ScheduledJobsConfig.runKeycloakUserReconciliationJob`)**:
   * Runs nightly at `02:00` (`ocsp.jobs.keycloak-reconciliation.cron: 0 0 2 * * *`).
   * Calls `KeycloakAdminClient.listAllUsers()` (via `ocsp-user-sync` service account), upserts all active Keycloak users into `ocsp.users`, and soft-deletes (`deleted_at`) any `KEYCLOAK` replica removed in Keycloak.

== 2. Failure Handling (`identity_outbox`)

No distributed (2PC) transactions are used between MariaDB and Keycloak:
* `KeycloakIdentityService` calls the Keycloak Admin API first before upserting the DB replica.
* For updates, enable/disable, password-reset emails, or deletes, if Keycloak is temporarily unreachable, `IdentityOutboxService` records a pending operation in `identity_outbox` (`Propagation.REQUIRES_NEW`).
* `ScheduledJobsConfig.runIdentityOutboxRetryJob()` retries pending entries every `30s` (`ocsp.jobs.identity-outbox-retry.fixed-delay-ms`) up to `max-attempts` (`5`).

== 3. Mode Migration Procedure (`SELF_MANAGEMENT` <-> `KEYCLOAK`)

[IMPORTANT]
.Mode Migration Is a Procedure, Not a Config Flip
====
Flipping `app.auth.mode` without migrating identities will break user logins or create orphaned accounts because `SELF_MANAGEMENT` authenticates against `password_hash` while `KEYCLOAK` joins on `external_id` (`sub`).
====

=== Migrating `SELF_MANAGEMENT` -> `KEYCLOAK`
1. **Freeze user mutations** in `ocsp-console` during the maintenance window.
2. **Export users** from `ocsp.users` (`username`, `email`, `full_name`, `enabled`, `roles`) and import them into Keycloak via the Admin REST API (preserving `emailVerified=true` for verified emails or requiring password reset on first login via `UPDATE_PASSWORD`).
3. **Populate `external_id`** (or let JIT provisioning link accounts on verified-email match) and set `auth_source = 'KEYCLOAK'` and `password_hash = NULL` on migrated rows.
4. **Update configuration**: Set `app.auth.mode=KEYCLOAK` (`APP_AUTH_MODE=KEYCLOAK`) and deploy.
5. **Run reconciliation**: Verify `KeycloakSyncService.reconcileAllFromKeycloak()` reports 100% parity.

=== Migrating `KEYCLOAK` -> `SELF_MANAGEMENT`
1. **Freeze user mutations** in Keycloak and `ocsp-console`.
2. **Set `auth_source = 'LOCAL'`** on active `users` rows and require every user to complete a **one-time password setup / reset** (because `password_hash` is `NULL` for Keycloak users).
3. **Update configuration**: Set `app.auth.mode=SELF_MANAGEMENT` (`APP_AUTH_MODE=SELF_MANAGEMENT`) and deploy.

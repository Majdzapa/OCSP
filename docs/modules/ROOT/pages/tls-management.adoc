= TLS Security Configuration
:toc:

Transport Layer Security (TLS) settings for both the RabbitMQ messaging channel and OCSP login metadata are externalized into `application.yml` / `application-dev.yml` and bound via `AppSecurityProperties` and `RabbitMqTlsProperties`.

== TLS Configuration Properties

[source,yaml]
----
security:
  tls:
    enabled: ${SECURITY_TLS_ENABLED:${AUTH_TLS_ENABLED:${TLS_ENABLED:true}}}

rabbitmq:
  tls:
    enabled: ${RABBITMQ_TLS_ENABLED:${security.tls.enabled:true}}
    tls-port: ${RABBITMQ_TLS_PORT:5671}
    plaintext-port: ${RABBITMQ_PLAINTEXT_PORT:5672}
----

[cols="1,2,2", options="header"]
|===
| Dimension | Enabled (`true`) | Disabled (`false`)

| *RabbitMQ Connection (`RabbitMqTlsProperties`)*
| Strict mutual TLS (AMQPS) on `tls-port` (`5671`) using PKCS#12 client keystore & truststore (`verify_peer`).
| `RabbitMqConfig.rabbitMqTlsPortCustomizer()` switches connection factory port from `5671` to `plaintext-port` (`5672`).

| *Auth & Dashboard Metadata (`AppSecurityProperties`)*
| `GET /api/v1/auth/config` and `GET /api/v1/admin/dashboard/stats` report `tlsEnabled: true`, `ocspLoginTlsEnabled: true`, and `messagingBroker: "RabbitMQ (AMQPS / Strict mTLS)"`.
| Reports `tlsEnabled: false` and `messagingBroker: "RabbitMQ (Plaintext)"`.
|===

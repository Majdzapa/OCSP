= Multi-CA Signing Certificates, Daily Validity Job & Renewal
:toc:

The OCSP Responder supports multi-CA delegated OCSP signing certificates (`id-kp-OCSPSigning`) backed by SoftHSM2 PKCS#11 private keys, post-commit in-memory synchronization, a daily midnight validity check cron job, 3-day expiry alerting, and one-click HSM renewal CSR generation.

== Multi-CA Active Signing Certificates

Unlike legacy single-CA responders:

* **Multiple signing certificates can be active simultaneously** (e.g., one RSA signing certificate issued by `Root CA A` and one ECDSA P-256 signing certificate issued by `Subordinate CA B`).
* When an RFC 6960 request arrives, `MultiProviderOcspSigner.selectSigner(CertificateID)` inspects the request's `CertID` (`issuerNameHash` and `issuerKeyHash`) and selects the active, non-expired signing certificate issued by that CA.
* Operators cannot deactivate or delete the last remaining active signing certificate while it is active.

== Post-Commit In-Memory Signer Synchronization

When an administrator imports, activates, deactivates, or deletes a signing certificate:

1. `SigningCertificateService` updates `ocsp.signing_certificates` inside a `@Transactional` boundary (using `FindSigningCertificateUseCase` for lookups) and publishes a `SigningConfigurationChangedEvent`.
2. `@TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT, fallbackExecution = true)` runs `onSigningConfigurationChanged(...)` only **after** the database transaction commits.
3. It calls `ocspSigner.updateActiveCertificate(...)` and `syncAllSignersWithHsm()`, which reloads all non-expired active certificates into `MultiProviderOcspSigner`.

== Daily Signing Certificate Validity Check & 3-Day Alert Monitor

Configured via `ScheduledJobsProperties` (`ocsp.jobs.signing-cert-validity.*`) and triggered by `ScheduledJobsConfig.runDailySigningCertificateValidityJob()`:

* **Schedule**: Default `0 0 0 * * *` (every day at 00:00), plus once on `ApplicationReadyEvent` and on demand via `POST /api/v1/admin/signing-certificates/validity/check`.
* **Alert Threshold**: Default `3` days (`72` hours).
* **Classification**:
  - `HEALTHY`: More than `alert-threshold-days` remaining.
  - `EXPIRING_SOON`: Not expired, and remaining validity `<= alert-threshold-days` (logs `[SIGNING-CERT-ALERT] [EXPIRING_SOON]`).
  - `EXPIRED`: `now.isAfter(notAfter)` (logs `[SIGNING-CERT-ALERT] [EXPIRED]`).
* **One-Click HSM Renewal CSR** (`POST /api/v1/admin/signing-certificates/\{id\}/renew-request`):
  Generates a fresh PKCS#10 CSR for the expiring certificate (reusing its existing SoftHSM2 keypair by default, or generating a new HSM keypair when `reuseExistingKey=false`).

== REST API Reference

[cols="1,2,3", options="header"]
|===
| Method | Path | Description

| `GET`
| `/api/v1/admin/signing-certificates`
| Lists all registered signing certificates with status and expiry.

| `GET`
| `/api/v1/admin/signing-certificates/active`
| Returns the primary active signing certificate.

| `GET`
| `/api/v1/admin/signing-certificates/hsm`
| Returns SoftHSM2 token metadata and all PKCS#11 key labels.

| `POST`
| `/api/v1/admin/signing-certificates/csr`
| Generates an HSM keypair (RSA/EC) on demand and returns a PKCS#10 CSR PEM.

| `POST`
| `/api/v1/admin/signing-certificates`
| Verifies public-key match with HSM keypair, imports certificate to token, and saves to DB.

| `PUT`
| `/api/v1/admin/signing-certificates/\{id\}/activate`
| Activates the certificate and triggers post-commit HSM signer sync.

| `PUT`
| `/api/v1/admin/signing-certificates/\{id\}/deactivate`
| Deactivates the certificate (provided at least one active certificate remains).

| `DELETE`
| `/api/v1/admin/signing-certificates/\{id\}`
| Deletes an inactive signing certificate.

| `GET`
| `/api/v1/admin/signing-certificates/validity`
| Returns the live validity report and active 3-day expiry alerts.

| `POST`
| `/api/v1/admin/signing-certificates/validity/check`
| Triggers an immediate validity check across all signing certificates.

| `POST`
| `/api/v1/admin/signing-certificates/\{id\}/renew-request`
| Generates a PKCS#10 renewal CSR in SoftHSM2 for the specified signing certificate.
|===

== Admin Console Screens (`http://localhost:3002`)

* **Signing Certificates (`http://localhost:3002/signing-certificates`)**: Generate HSM keypairs & CSRs, import CA-signed `OCSP_SIGNING` PEMs, and activate/deactivate certificates.
* **Signing Validity & Alerts (`http://localhost:3002/signing-validity`)**: View the daily cron status, 3-day expiry alert banners, per-certificate countdowns, and one-click **Renew (Generate HSM CSR)** modal.

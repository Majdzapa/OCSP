== Sequence Diagram 1: On-Demand HSM CSR, KMS Issuance & Post-Commit Activation

[source,mermaid]
----
sequenceDiagram
    autonumber
    actor Admin as PKI Administrator
    participant Console as OCSP Console (:3002)
    participant Responder as SigningCertificateService (:8080)
    participant HSM as SoftHSM2 (PKCS#11)
    participant KMS as KMS Simulator (:3001 / :8090)
    participant DB as OCSP MariaDB (:3307)

    Note over Responder,HSM: Before activation, POST /ocsp returns TRY_LATER (3)
    Admin->>Console: Request New HSM Keypair & CSR (keyLabel, subjectDn, RSA-3072 / EC-P256)
    Console->>Responder: POST /api/v1/admin/signing-certificates/csr
    Responder->>HSM: Generate non-extractable keypair (CKA_EXTRACTABLE=FALSE) & sign PKCS#10 CSR
    HSM-->>Responder: CSR PEM (-----BEGIN CERTIFICATE REQUEST-----)
    Responder-->>Console: GenerateCsrResponse (csrPem, publicKeyAlgorithm, keySize)

    Admin->>KMS: Issue Certificate from CSR with profile OCSP_SIGNING (id-kp-OCSPSigning)
    KMS-->>Admin: Signed X.509 OCSP Signing Certificate PEM

    Admin->>Console: Upload Signed PEM & Activate
    Console->>Responder: POST /api/v1/admin/signing-certificates
    Responder->>HSM: Verify cert PublicKey matches HSM keyLabel & import to PKCS#11 token
    Responder->>DB: INSERT INTO signing_certificates (active=true) & COMMIT
    Responder->>Responder: @TransactionalEventListener(AFTER_COMMIT) -> syncAllSignersWithHsm()
    Responder-->>Console: HTTP 201 Created (Signer Active)
----

== Sequence Diagram 2: Strict RFC 6960 `CertID` Verification (`GOOD` vs `UNKNOWN`)

[source,mermaid]
----
sequenceDiagram
    autonumber
    actor Verifier as Operator (:3002/cert-checker or :8082)
    participant ClientSvc as OcspClientService (:8082)
    participant Responder as OcspResponderService (:8080)
    participant StatusSvc as CertificateStatusService
    participant DB as OCSP MariaDB (revocation_status)
    participant HSM as MultiProviderOcspSigner / SoftHSM2

    Verifier->>ClientSvc: POST /api/v1/client/check { serialNumberHex, caPem, useNonce: true }
    ClientSvc->>ClientSvc: Compute CertID(SHA-1(caSubject), SHA-1(caPublicKey), serial) + 8B Nonce
    ClientSvc->>Responder: POST /ocsp (DER OCSPRequest)
    Responder->>StatusSvc: findByCertId(issuerNameHash, issuerKeyHash, serialBytes)
    StatusSvc->>DB: SELECT * FROM revocation_status WHERE issuer_name_hash=? AND issuer_key_hash=? AND serial_number=?
    alt Matching Issuer CA PEM & Active Serial
        DB-->>StatusSvc: Row(status=GOOD)
        StatusSvc-->>Responder: Optional.of(GOOD)
    else Wrong Issuer CA PEM (Hashes Do Not Match Issuing CA)
        DB-->>StatusSvc: Empty (No Serial-Only Fallback)
        StatusSvc-->>Responder: Optional.empty() -> UnknownStatus
    end
    Responder->>HSM: selectSigner(CertID) & Sign BasicOCSPResp (echoing 8B Nonce)
    HSM-->>Responder: Signed OCSPResp DER
    Responder-->>ClientSvc: HTTP 200 OK (application/ocsp-response)
    ClientSvc-->>Verifier: Detailed Diagnostic Report (Cert Status, Signature Valid, Nonce Match)
----

== Sequence Diagram 3: Pure RabbitMQ 3s Manifest Audit & Self-Healing Replay

[source,mermaid]
----
sequenceDiagram
    autonumber
    participant KMS as KMSReconciliationService (:8090)
    participant KMS_DB as KMS MariaDB (:3308)
    participant Broker as RabbitMQ (:5671 mTLS)
    participant OCSP_Rec as OutboxReconciliationService (:8080)
    participant OCSP_DB as OCSP MariaDB (:3307)

    loop Every 3000ms
        KMS->>KMS_DB: Read all certificates & outbox_event rows
        KMS->>Broker: Publish OutboxManifestEvent (ocsp.reconciliation.manifest)
        Broker->>OCSP_Rec: Deliver OutboxManifestEvent (cached in latestManifestRef)
    end

    Note over OCSP_Rec,OCSP_DB: Operator clicks "Replay Missing / Failed via RabbitMQ" on :3002/inbox
    OCSP_Rec->>OCSP_DB: Diff manifest against inbox_event & revocation_status
    OCSP_Rec->>Broker: Publish ReconciliationCommandMessage(REPLAY_EVENTS, eventIds, serials)
    Broker->>KMS: Deliver to kms.reconciliation.request
    KMS->>KMS_DB: Reset sent=false on matching outbox_event rows
    KMS->>KMS_DB: Synthesize fresh OutboxEvent for any requested serial missing from outbox_event
    KMS->>Broker: Immediate OutboxRelayJob flush -> ocsp.certificate.status
    Broker->>OCSP_DB: CertificateStatusConsumerService updates revocation_status & marks inbox PROCESSED
----

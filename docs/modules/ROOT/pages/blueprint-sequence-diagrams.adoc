== RFC 6960 Protocol Compliance Guarantees

[cols="2,3,4", options="header"]
|===
| Protocol Dimension | RFC 6960 / RFC 5019 Standard | Incert Subsystem Implementation

| *Transport Wire Formats*
| ASN.1 DER over HTTP POST and Base64URL over HTTP GET.
| Supports `POST /ocsp` (`Content-Type: application/ocsp-request`) and `GET /ocsp/\{base64url\}` with RFC-compliant validation.

| *Issuer Identification*
| IssuerNameHash and IssuerKeyHash.
| Computes SHA-1/SHA-256 digests against known CA certificates. Mismatches return status `UNKNOWN`.

| *Status Categorization*
| `GOOD`, `REVOKED`, `UNKNOWN`.
| Maps directly to database state. `REVOKED` includes UTC ISO timestamp and CRLReason code.

| *Anti-Replay / Nonce*
| Section 4.4.1 Nonce Extension.
| If present in the request, extracts and includes identical nonce in response. If absent, applies RFC 5019 `nextUpdate` window.

| *Temporal Freshness*
| `thisUpdate` and `nextUpdate`.
| Evaluates `thisUpdate = now()`, `nextUpdate = now() + 24h` (configurable via `OCSP_NEXT_UPDATE_WINDOW`).

| *Hardware Signature*
| Delegated OCSP Responder Signature.
| Signed using SHA256withRSA inside SoftHSM2/physical HSM via SunPKCS11. Key usage `id-kp-OCSPSigning` enforced.
|===

== Sequence Diagram 1: Synchronous RFC 6960 Validation Flow

[source,mermaid]
----
sequenceDiagram
    autonumber
    actor Client as Relying Party (Browser / TLS Client)
    participant Nginx as Nginx Proxy (:3000)
    participant OcspCtrl as OcspResponderController
    participant Parser as OcspResponderService (ASN.1 DER Engine)
    participant DB as MariaDB (revocation_status)
    participant Signer as Pkcs11OcspSigner
    participant HSM as SoftHSM2 (PKCS#11 Token)

    Client->>Nginx: POST /ocsp (Content-Type: application/ocsp-request)
    Note over Client,Nginx: Contains ASN.1 DER OCSPRequest with SerialNumber & Optional Nonce
    Nginx->>OcspCtrl: Forward binary payload
    OcspCtrl->>Parser: processOcspRequest(requestBytes)
    
    Parser->>Parser: Parse ASN.1 DER with BouncyCastle
    Parser->>Parser: Extract CertID (IssuerNameHash, IssuerKeyHash, SerialNumber)
    Parser->>Parser: Extract Nonce Extension (if present)

    Parser->>DB: SELECT * FROM revocation_status WHERE serial_number = ? AND issuer_name_hash = ?
    alt Certificate Found and Revoked
        DB-->>Parser: Record(status=REVOKED, revocation_time=T, reason=KEY_COMPROMISE)
        Parser->>Parser: Build RevokedStatus(revocationDate, CRLReason)
    else Certificate Found and Active
        DB-->>Parser: Record(status=GOOD)
        Parser->>Parser: Build GoodStatus()
    else Certificate Not Found
        DB-->>Parser: null
        Parser->>Parser: Build UnknownStatus()
    end

    Parser->>Parser: Calculate thisUpdate = now(), nextUpdate = now() + 24h
    opt Nonce Present in Request
        Parser->>Parser: Add Nonce extension to response matching request
    end

    Parser->>Signer: signResponse(basicResponseBuilder)
    Signer->>HSM: C_SignInit(CKM_SHA256_RSA_PKCS, KeySlot)
    Signer->>HSM: C_Sign(derDigest)
    Note over Signer,HSM: Private key never leaves HSM boundary (CKA_EXTRACTABLE=FALSE)
    HSM-->>Signer: Raw Cryptographic Signature
    Signer-->>Parser: Signed OCSPResp Object

    Parser-->>OcspCtrl: Encoded OCSPResp (application/ocsp-response DER)
    OcspCtrl-->>Nginx: HTTP 200 OK + Cache-Control: max-age=86400, ETag
    Nginx-->>Client: Binary OCSP Response DER
    Client->>Client: Verify signature using Responder Certificate & validate TLS handshake
----

== Sequence Diagram 2: Asynchronous Revocation Ingestion (Outbox & Strict mTLS)

[source,mermaid]
----
sequenceDiagram
    autonumber
    actor SecAdmin as PKI Security Operator
    participant KMS as KMS / CA Simulator (:8090)
    participant KMS_DB as MariaDB (kms schema)
    participant OutboxRelay as KMS Outbox Poller
    participant Rabbit as RabbitMQ Broker (Port 5671 strict mTLS)
    participant Consumer as CertificateStatusListener (:8080)
    participant OCSP_DB as MariaDB (ocsp schema)

    SecAdmin->>KMS: POST /kms/certificates/\{serial\}/revoke (reason: KEY_COMPROMISE)
    activate KMS
    rect rgb(240, 248, 255)
        Note over KMS,KMS_DB: Atomic ACID Transaction
        KMS->>KMS_DB: UPDATE certificates SET status = 'REVOKED' WHERE serial = ?
        KMS->>KMS_DB: INSERT INTO outbox_event (id, event_type, payload, status='PENDING')
    end
    KMS-->>SecAdmin: HTTP 200 OK (Revocation Acknowledged)
    deactivate KMS

    loop Background Outbox Relay (Every 1000ms)
        OutboxRelay->>KMS_DB: SELECT * FROM outbox_event WHERE status = 'PENDING'
        KMS_DB-->>OutboxRelay: List of pending revocation events
        OutboxRelay->>Rabbit: Publish over AMQPS (Port 5671 mTLS, Exchange: incert.certificate.status)
        Note over OutboxRelay,Rabbit: TLS Handshake verifies Client Certificate & Server Certificate
        Rabbit-->>OutboxRelay: Basic.Ack
        OutboxRelay->>KMS_DB: UPDATE outbox_event SET status = 'PUBLISHED'
    end

    Rabbit->>Consumer: Deliver AMQP Message (CertificateRevokedEvent)
    activate Consumer
    Consumer->>OCSP_DB: SELECT event_id FROM consumed_events WHERE event_id = ?
    alt Already Processed (Duplicate Detection)
        OCSP_DB-->>Consumer: Record exists
        Note over Consumer: Ignore duplicate event (Idempotent Guard)
        Consumer->>Rabbit: Basic.Ack
    else New Event
        OCSP_DB-->>Consumer: Record not found
        rect rgb(245, 255, 245)
            Note over Consumer,OCSP_DB: Atomic Responder Ingestion Transaction
            Consumer->>OCSP_DB: UPSERT INTO revocation_status (serial, status='REVOKED', revocation_time, reason)
            Consumer->>OCSP_DB: INSERT INTO consumed_events (event_id, processed_at)
        end
        Consumer->>Rabbit: Basic.Ack
    end
    deactivate Consumer
----

== Sequence Diagram 3: Zero-Downtime Dynamic Signing Certificate Rotation

[source,mermaid]
----
sequenceDiagram
    autonumber
    actor Admin as PKI Administrator
    participant UI as Mantine Web Console (:3000)
    participant Nginx as Nginx Reverse Proxy
    participant Ctrl as SigningCertificateController (:8080)
    participant Service as SigningCertificateService
    participant DB as MariaDB (ocsp_signing_certificates)
    participant Signer as Pkcs11OcspSigner
    participant HSM as SoftHSM2 / Physical HSM

    Admin->>UI: Upload New Responder Certificate (X.509 PEM + Key Alias)
    UI->>Nginx: POST /api/v1/certificates/signing
    Nginx->>Ctrl: Forward request with Admin Authorization
    Ctrl->>Service: addCertificate(dto)
    
    Service->>Service: Validate X.509 certificate expiry & KeyUsage (id-kp-OCSPSigning)
    Service->>DB: INSERT INTO ocsp_signing_certificates (name, pem, key_alias, is_active=false)
    DB-->>Service: Saved Certificate ID = 42
    Service-->>Ctrl: Certificate DTO (Status: Inactive)
    Ctrl-->>UI: HTTP 201 Created

    Admin->>UI: Click "Activate Certificate" for ID = 42
    UI->>Nginx: POST /api/v1/certificates/signing/42/activate
    Nginx->>Ctrl: Forward Activation Request
    Ctrl->>Service: activateCertificate(42)

    rect rgb(255, 250, 240)
        Note over Service,DB: Atomic Database State Transition
        Service->>DB: UPDATE ocsp_signing_certificates SET is_active = false WHERE is_active = true
        Service->>DB: UPDATE ocsp_signing_certificates SET is_active = true WHERE id = 42
    end

    Service->>Signer: reloadActiveCertificate()
    Signer->>DB: SELECT * FROM ocsp_signing_certificates WHERE is_active = true
    DB-->>Signer: Return Certificate (ID: 42, Key Alias: "ocsp-slot-2026")
    Signer->>HSM: Verify Slot & Key Alias Access (CKA_LABEL="ocsp-slot-2026")
    HSM-->>Signer: Key Validated & Session Ready
    Signer->>Signer: Atomically swap in-memory reference to new X509CertificateHolder & PrivateKey
    
    Signer-->>Service: Rotation Completed Successfully
    Service-->>Ctrl: Success DTO
    Ctrl-->>UI: HTTP 200 OK (New Certificate is Active)
    Note over Admin,HSM: Subsequent OCSP requests are immediately signed with the new certificate!
----

== Sequence Diagram 5: Standalone Cryptographic Verifier Flow

[source,mermaid]
----
sequenceDiagram
    autonumber
    actor Auditor as Security Auditor / Tester
    participant ClientUI as OCSP Verifier UI (:8082)
    participant ClientSvc as OcspClientService (:8082)
    participant Responder as OCSP Responder (:8080)
    participant RootCA as Trusted Root CA Certificate

    Auditor->>ClientUI: Submit Verification Form (Target Certificate PEM + Issuer CA PEM)
    ClientUI->>ClientSvc: POST /api/v1/client/check { targetCert, issuerCert, useNonce: true }
    
    ClientSvc->>ClientSvc: Generate Cryptographically Secure 16-byte Nonce
    ClientSvc->>ClientSvc: Build ASN.1 OCSPReq with CertID & Nonce Extension
    
    ClientSvc->>Responder: POST /ocsp (DER payload)
    Responder-->>ClientSvc: HTTP 200 OK + OCSPResp (DER payload)

    ClientSvc->>ClientSvc: 1. Validate OCSP Response Status == SUCCESSFUL (0)
    ClientSvc->>ClientSvc: 2. Parse BasicOCSPResp & Extract Responder Certificate
    ClientSvc->>RootCA: 3. Verify Responder Cert was signed by Trusted Issuer CA (or is CA itself)
    ClientSvc->>ClientSvc: 4. Check ExtendedKeyUsage contains id-kp-OCSPSigning (OID 1.3.6.1.5.5.7.3.9)
    ClientSvc->>ClientSvc: 5. Verify Cryptographic Signature on BasicOCSPResp with Responder Public Key
    ClientSvc->>ClientSvc: 6. Match Response Nonce against Sent Nonce (Anti-Replay Verification)
    ClientSvc->>ClientSvc: 7. Validate Time Window: thisUpdate <= now() <= nextUpdate
    ClientSvc->>ClientSvc: 8. Extract Target Certificate Status: GOOD / REVOKED / UNKNOWN

    ClientSvc-->>ClientUI: VerificationResultDTO { verified: true, signatureValid: true, nonceValid: true, status: "GOOD" }
    ClientUI-->>Auditor: Render Green Badge "Cryptographically Valid & Authorized by CA"
----

= Verification & Testing Suite
:toc:

The Incert OCSP Subsystem includes comprehensive JUnit 5 unit test suites in both `ocsp-responder` and `ocsp-client`, as well as end-to-end verification workflows covering the full v5.0 zero-static-data lifecycle.

== Running Unit Tests

[source,bash]
----
mvn -f ocsp-responder/pom.xml test
mvn -f ocsp-client/pom.xml test
----

=== Unit Test Coverage Matrix

[cols="2,3", options="header"]
|===
| Test Class | Verified Behavior

| `CertificateStatusServiceTest`
| Strict 3-tuple RFC 6960 `CertID` lookup `(issuer_name_hash, issuer_key_hash, serial_number)`, confirming that querying an existing serial with a different CA's hashes returns `Optional.empty()` (`UNKNOWN`), plus monotonic `sequence` guard and canonical serial hex parsing via `CanonicalizeSerialHexUseCase`.

| `OcspResponderServiceTest`
| RFC 6960 `TRY_LATER (3)` when unprovisioned, `GOOD`/`REVOKED`/`UNKNOWN` DER responses, RFC 8954 Nonce echoing, and request size / CertID count / nonce length limits bound via `OcspResponderProperties`.

| `SigningCertificateServiceTest`
| On-demand CSR generation, public-key match validation, multi-CA activation/deactivation via `FindSigningCertificateUseCase`, and post-commit `@TransactionalEventListener(AFTER_COMMIT)` signer synchronization.

| `SigningCertificateValidityServiceTest`
| Daily validity evaluation bound via `ScheduledJobsProperties`, 3-day expiry alert detection (`HEALTHY`, `EXPIRING_SOON`, `EXPIRED`), and one-click HSM renewal CSR generation (`createRenewalRequest`).

| `OutboxReconciliationServiceTest`
| RabbitMQ `OutboxManifestEvent` consumption, diffing against `ocsp.inbox_event` and `ocsp.revocation_status`, and publishing `REPLAY_EVENTS` `ReconciliationCommandMessage` over RabbitMQ.

| `CertificateStatusConsumerServiceTest`
| Idempotent inbox deduplication (`PROCESSED` vs `DUPLICATE`) and poison-pill failure recording with `AmqpHeaders.MESSAGE_ID` and `AmqpHeaders.DELIVERY_TAG` via `InboxFailureRecorder`.

| `AuthControllerTest` & `AdminDashboardControllerTest`
| `KEYCLOAK` and `SELF_MANAGED` authentication modes bound via `AppSecurityProperties`, `AdminProperties`, `KeycloakProperties`, and `RabbitMqTlsProperties`.

| `OcspClientServiceTest`
| Standalone client RFC 6960 request building (with Issuer CA PEM), signature verification, nonce echo validation, and HTTP error handling bound via `OcspClientProperties`.
|===

== End-to-End Verification Workflow (Zero Static Data)

1. **Unprovisioned Safety Check**: Query `POST http://localhost:8080/ocsp` before activating any signing certificate -> verify `OCSPRespStatus = TRY_LATER (3)`.
2. **CA Creation in KMS (`http://localhost:3001/cas`)**: Create a Root CA (RSA 3072 or EC P-256) and optionally a Subordinate CA.
3. **HSM Keypair & CSR -> KMS Issuance -> Activation (`http://localhost:3002/signing-certificates`)**:
   * Generate a new SoftHSM2 keypair and PKCS#10 CSR.
   * Issue an `OCSP_SIGNING` certificate in KMS (`http://localhost:3001/certificates`).
   * Import and activate the signed PEM in OCSP Admin.
4. **Strict RFC 6960 `CertID` Check (`http://localhost:3002/cert-checker` & `http://localhost:8082`)**:
   * Verify an issued certificate with its **matching Issuer CA PEM** -> returns `GOOD` with valid signature and 8-byte Nonce echo.
   * Verify the same serial with a **different CA's PEM** -> returns `UNKNOWN`.
5. **RabbitMQ Outbox ↔ Inbox Reconciliation & Replay (`http://localhost:3002/inbox`)**:
   * Confirm 3-second `OutboxManifestEvent` parity (`synchronized: true`).
   * Trigger **Replay Missing / Failed via RabbitMQ** and verify self-healing recovery (including when an outbox row is missing for an existing certificate serial).
6. **Daily Validity Check & 1-Click Renewal (`http://localhost:3002/signing-validity`)**:
   * Run **Check Validity Now** and verify `HEALTHY` / `EXPIRING_SOON` / `EXPIRED` classification and one-click HSM renewal CSR generation.

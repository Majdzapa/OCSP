= Incert OCSP Subsystem v5.0
:description: High-performance, Zero-Static-Data RFC 6960 Online Certificate Status Protocol (OCSP) Responder with SoftHSM2 PKCS#11, RabbitMQ mTLS, and Multi-CA Signing
:keywords: ocsp, pki, rfc6960, rfc8954, cryptography, hsm, pkcs11, rabbitmq, mtls, keycloak, outbox, inbox

Welcome to the official documentation for the **Incert OCSP Subsystem v5.0**. This system implements an enterprise-grade, zero-static-data **RFC 6960** and **RFC 8954** Online Certificate Status Protocol (OCSP) responder with hardware-backed **SoftHSM2 PKCS#11** signing, **RabbitMQ strict mutual TLS (mTLS)** event synchronization, **pure RabbitMQ Outbox ↔ Inbox reconciliation**, and a **Daily Signing Certificate Validity & 3-Day Alert Monitor**.

== Highlights & v5.0 Capabilities

[cols="1,3", options="header"]
|===
| Capability | v5.0 Implementation Details

| *Zero Static Data PKI Architecture*
| No pre-seeded CA certificates, end-entity certificates, HSM private keys, or signing certificates exist at startup. Before an operator provisions an HSM keypair, exports a PKCS#10 CSR, signs it in KMS (`OCSP_SIGNING`), and activates it, the responder safely returns RFC 6960 `tryLater (3)`.

| *Strict RFC 6960 `CertID` Matching*
| Every OCSP query (`POST /ocsp` and `GET /ocsp/\{base64url\}`) verifies the full RFC 6960 `CertID` tuple `(issuer_name_hash, issuer_key_hash, serial_number)` without any serial-only fallback. Supplying a different Issuer CA PEM produces distinct `issuerNameHash` / `issuerKeyHash` values and deterministically returns `UNKNOWN`.

| *On-Demand SoftHSM2 PKCS#11 Keygen & Multi-CA Signing*
| Non-extractable (`CKA_EXTRACTABLE = FALSE`) RSA (`2048`/`3072`/`4096`) and EC (`P-256`/`P-384`) keypairs are generated on demand inside SoftHSM2 when creating a CSR. Multiple signing certificates (one per issuing CA) can be active simultaneously and are reloaded post-commit via `@TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)`.

| *Pure RabbitMQ 3s Outbox ↔ Inbox Audit & Self-Healing*
| Zero REST coupling between KMS and OCSP. KMS broadcasts an `OutboxManifestEvent` over RabbitMQ every 3 seconds. `OutboxReconciliationService` compares outbox event IDs and certificate digests against `ocsp.inbox_event` and `ocsp.revocation_status`, tracks failed deliveries via `AmqpHeaders.MESSAGE_ID` and `AmqpHeaders.DELIVERY_TAG`, and triggers `REPLAY_EVENTS` over RabbitMQ (synthesizing missing outbox events if needed).

| *Centralized Scheduled Jobs & Daily Validity Monitor*
| All `@Scheduled` triggers in the responder live in `com.company.incert.ocsp.config.ScheduledJobsConfig` and bind from `ScheduledJobsProperties` (`ocsp.jobs.*`). The daily midnight job (`0 0 0 * * *`) checks all signing certificates, raises a 3-day expiry alert (`EXPIRING_SOON` / `EXPIRED`), and powers one-click HSM renewal CSRs on `/signing-validity`.

| *Zero Hardcoded Config & Clean Use Cases*
| 100% of configuration values live in `application.yml`, `application-dev.yml`, and `application-local.yml`, bound into typed `@ConfigurationProperties` classes under `config`. Reusable domain actions live in `com.company.incert.ocsp.usecase` (`FindSigningCertificateUseCase`, `CanonicalizeSerialHexUseCase`).

| *Plain JavaScript (`.js`) React 18 Admin Console*
| `ocsp-console` (served on port `3002`) is built with React 18, Mantine v7, and Vite using clean `.js` modules (`jsconfig.json`) with no TypeScript compilation step.
|===
